Redux: Key Concepts in 5 Minutes

Redux is a predictable state container for JavaScript apps. It helps you manage global state in a structured, consistent way.

The Core Flow

Redux follows a strict, unidirectional data flow. This makes debugging easier and state changes predictable.

[Image of Redux data flow architecture showing Store, Action, Dispatch, and Reducer]

The 3 Pillars

  • Store: The "Single Source of Truth." It holds the entire state tree of your application. You should never modify it directly.
  • Actions: Plain JavaScript objects that describe *what* happened (e.g., { type: 'INCREMENT' }). They are the only way to trigger a state change.
  • Reducers: Pure functions that take the current state and an action, and return a new state. They define how the state transitions.

Simple Example: A Counter

const initialState = { count: 0 };

function counterReducer(state = initialState, action) {
  switch (action.type) {
    case 'INCREMENT':
      return { count: state.count + 1 };
    default:
      return state;
  }
}

const action = { type: 'INCREMENT' };

Key Rules to Remember

  • State is Read-Only: You cannot change the state directly. You must dispatch an action.
  • Changes are Pure: Reducers must be pure functions. Given the same input, they must always return the same output without side effects (no API calls inside reducers!).
  • Unidirectional Data Flow: View -> Action -> Dispatch -> Reducer -> Store -> View.
