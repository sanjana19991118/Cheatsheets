Built-in Hooks
What are Hooks?
The big idea
Hooks are functions that let function components "hook into" React features — state, lifecycle, context, refs — without writing a class. Introduced in React 16.8, they replace class-based patterns entirely.
All hook names start with use — this convention lets React (and linters) enforce the Rules of Hooks automatically.
Why hooks over classes?
  • No more confusing this binding
  • Reuse stateful logic between components (custom hooks)
  • Split one component into smaller functions by concern
  • Functions are easier to test and reason about
  • Smaller bundle size — no class boilerplate

The 2 rules of hooks
✓ Rule 1
Only call at the top level
Never call hooks inside loops, conditions, or nested functions. React relies on hook call order being stable between renders.
// ✓ Always at top level
function Component() {
  const [x, setX] = useState(0);
  // ← always runs, always first
}
✕ Don't do this
Conditional hook calls
React numbers hooks by call order. If you skip one, every subsequent hook gets the wrong state bucket — bugs guaranteed.
// ✕ Never inside a condition
if (condition) {
  const [x, setX] = useState(0);
  // ← breaks hook ordering!
}
✓ Rule 2
Only call from React functions
Only call hooks from function components or your own custom hooks. Not from regular JS functions, classes, or event handlers.
// ✓ Function component
function MyComponent() { useEffect(...) }
// ✓ Custom hook
function useMyHook() { useState(...) }
✕ Not here
Regular functions / classes
Hooks only work inside React's render cycle. Outside it, React's state tracking machinery doesn't exist.
// ✕ Plain JS function
function helper() { useState(...) }
// ✕ Class component
class Foo { render() { useState(...) }}

useState — local state
useState(initialValue) most used hook — local reactive state
How it works
  • Returns [value, setter] pair
  • Calling setter schedules a re-render
  • State is preserved between renders
  • Pass a function as initial value for lazy init
  • Setter can take a value or an updater function prev => next

Example
function Counter() {
  const [count, setCount] = useState(0);

  // updater fn — safe for batched updates
  const inc = () =>
    setCount(prev => prev + 1);

  return (
    <button onClick={inc}>
      Clicks: {count}
    </button>
  );
}
useReducer(reducer, initialState) useState for complex state logic
When to prefer useReducer
  • Multiple related state values that change together
  • Next state depends on previous in complex ways
  • State transitions need to be predictable / testable
  • Resembles Redux pattern — action + reducer
Example
function reducer(state, action) {
  switch (action.type) {
    case 'inc':
      return { count: state.count + 1 };
    default: return state;
  }
}

const [state, dispatch] = useReducer(
  reducer, { count: 0 }
);
dispatch({ type: 'inc' });
useEffect — side effects
useEffect(fn, deps?) runs after paint — data fetching, subscriptions, DOM mutations
Key behaviours
  • Runs after browser has painted
  • Return a cleanup function to avoid memory leaks
  • Deps array controls when it re-runs
  • useLayoutEffect fires before paint — use only for DOM measurements
useEffect(fn)
Runs every render
useEffect(fn, [])
Mount only
useEffect(fn, [x])
When x changes
Example with cleanup
useEffect(() => {
  const id = setInterval(() => {
    setTime(Date.now());
  }, 1000);

  // cleanup — runs on unmount
  // or before next effect fires
  return () => clearInterval(id);
}, []); // ← empty = run once
⚠ Every value used inside useEffect that can change must be in the deps array — the ESLint rule exhaustive-deps enforces this.
useRef & useContext
useRef(initialValue) mutable box, no re-render
Two uses
  • DOM access: ref={myRef} on an element — myRef.current is the DOM node
  • Mutable value: store any value that shouldn't trigger a re-render when changed (timers, previous values)
  • .current persists across renders
  • Changing .current does not cause a re-render
const inputRef = useRef(null);
// <input ref={inputRef} />
inputRef.current.focus();

Performance hooks — useMemo & useCallback
useMemo vs useCallback skip expensive recalculations between renders
Hook Memoises Use when Example
useMemo a computed value Expensive calculations (sort, filter, transform) that only need to re-run when deps change const sorted = useMemo(() => arr.sort(), [arr])
useCallback a function reference Passing callbacks to memoised child components — prevents unnecessary re-renders of the child const fn = useCallback(() => {}, [dep])
⚠ Don't reach for these first. Profile with React DevTools before optimising — premature memoisation adds complexity with no real gain on cheap operations.
Custom hooks — reuse stateful logic
The custom hook
// useWindowSize.js
import { useState, useEffect } from 'react';

export function useWindowSize() {
  const [size, setSize] = useState({
    w: window.innerWidth,
    h: window.innerHeight,
  });

  useEffect(() => {
    const handler = () =>
      setSize({ w: window.innerWidth,
               h: window.innerHeight });
    window.addEventListener('resize', handler);
    return () =>
      window.removeEventListener('resize', handler);
  }, []);

  return size;
}
Using it anywhere
import { useWindowSize } from './useWindowSize';

function Banner() {
  const { w, h } = useWindowSize();

  return <p>
    Window: {w} × {h}
  </p>;
}

function Sidebar() {
  const { w } = useWindowSize();
  // completely independent state copy
  return w < 768 ? <Drawer/> : <Rail/>;
}
Custom hooks share logic, not state. Each component calling useWindowSize() gets its own isolated state.
6 golden rules to remember
01
Top-level only
Never call hooks inside loops, conditions, or nested functions.
02
Prefer state over refs
Use useRef only when you genuinely don't want a re-render on change.
03
Clean up effects
Return a cleanup function from useEffect for subscriptions, timers, and event listeners.
04
Honest deps arrays
List every value your effect or memo reads. The exhaustive-deps ESLint rule is your friend.
05
Extract custom hooks
If two components share the same stateful logic, pull it into a useXxx custom hook.
06
Profile before optimising
Only reach for useMemo / useCallback after measuring a real performance problem.
