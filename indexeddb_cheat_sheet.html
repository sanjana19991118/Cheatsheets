IndexedDB: Key Concepts in 5 Minutes

IndexedDB is a low-level API for client-side storage of significant amounts of structured data, including files/blobs. It is a transactional, object-oriented database system built into the browser.

Architecture

[Image of IndexedDB architecture showing Database, Object Stores, Indexes, and Transactional flow]

Core Concepts

  • Database: The top-level container. You open it by name and version.
  • Object Store: Similar to a table in SQL. It stores data records (JavaScript objects).
  • Transaction: All operations (reading/writing) must happen within a transaction. It ensures atomicity (all-or-nothing).
  • Indexes: Specialized object stores used to look up records by a property other than the primary key.
  • Asynchronous: Most operations don't return values immediately; they return a request object that emits events (success/error).

Example: Adding Data

// 1. Open Database
const request = indexedDB.open('MyDatabase', 1);

request.onsuccess = (event) => {
  const db = event.target.result;
  // 2. Start Transaction
  const tx = db.transaction('users', 'readwrite');
  const store = tx.objectStore('users');

  // 3. Add Data
  store.add({ id: 1, name: 'Alice' });
};

Workflow Summary

  • Open the database.
  • Upgrade schema if version changes (create Object Stores here).
  • Create a transaction.
  • Access an Object Store.
  • Perform the request (add, get, put, delete).
